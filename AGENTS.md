# Project
Browser game "claim": canvas-based, vanilla JavaScript, no build step, no dependencies.
Run it by opening index.html in a browser. Voice filters, offline mode and the
service worker need http(s), e.g. `py -m http.server 8000` (the user starts it, not the agent).

# Structure
- index.html: markup only, loads the scripts in a fixed order
- css/claim.css: all styles
- js/: classic scripts (no modules) sharing one global scope, in load order:
  - core.js: constants, grid, canvas setup, shared state
  - gadgets.js: gadgets, mode/camera choice, most shared game state, power-up/perk/achievement definitions
  - level.js: level layout (pillars, pits, bonus zone), vision cone, smooth rotation
  - audio-sfx.js, audio-theme.js, audio-music.js: sound effects and music only
  - audio/voice/manifest.js (generated by tools/kokoro_voices.py), voice.js: spoken lines from MP3 files with filters, falls back to speechSynthesis
  - gameplay.js: level start, enemy spawning, shooting, power-ups, gadget use, player movement, capture (flood-fill, scoring), level complete
  - game.js: moving pillars, enemies, game over, shop, overlays
  - render-figures.js: figure drawing (duck, guard gear/eyes/vision cone/death, player face)
  - render-world.js: drawBoard(), drawWorldEffects(), drawWorldObjects() (field, popups, particles, power-ups, mines, decoys)
  - render-actors.js: drawPlayer(), drawGuards()
  - render-overlay.js: drawOverlays() (scene filter, PSYLO ghosting, fog, vignette, countdown), PSYLO offscreen state
  - render.js: draw(), one frame: camera/filter setup, then calls the parts above in draw order
  - ui.js: main loop, action buttons, start/pause/retry, mode select, quit
  - tutorial.js: tutorial
  - input.js: button, swipe and keyboard input, board background, resize, startup
  - qr.js: minimal QR code generator (2-player invite link)
  - net.js: peer-to-peer connection for 2-player mode (MQTT signaling, WebRTC)
  - versus-sim.js: 2-player versus, host simulation (state, capture, guards, mines, shots, snapshot)
  - versus-cpu.js: versus CPU opponent
  - versus-render.js: versus drawing (mirrors state into the 1-player globals, draws via draw())
  - versus.js: versus constants and state, lobby/panels, messages, input, loop, and the hook into the 1-player game (loads last)
  - splash.js: splash screen
  - pwa.js: service worker registration, background download of voices for offline play
- sw.js (root): service worker; manifest.webmanifest + icons/: home screen app
- audio/voice/: generated voice packs (<category>/<voice>.mp3, all lines concatenated) + manifest.js with byte ranges
- tools/voice_src/: single generated lines + manifest.json (generator source, not shipped)
- itch.io upload: zip everything except tools/ (max 1000 files)
- tools/kokoro_voices.py: local generator for the voice lines (Kokoro TTS, Python venv in tools/.venv).
  Reads the lines from the JS files; after changing spoken texts, the user re-runs it.

# Code rules
- No ES modules, no import/export. All scripts share the global scope.
- Code that runs at load time may only use things defined in earlier files.
  Calls inside functions or event handlers are fine.
- A new file needs a <script> tag in index.html at the right position.
- No new dependencies or build tools.

# Reading files
- Read only the files needed for the task.
- Skip audio-*.js unless the task is about sound or music.
- Read claim.css only for styling tasks.
- gameplay.js and render-actors.js are the largest files: use grep to find the relevant function, then read only that range.
- For drawing tasks: draw() in render.js passes its per-frame locals (e.g. blinkOnGlobal, pcx, pcy) to the parts as parameters, so a part cannot see draw()'s other locals.

# Working style
- Think briefly and purposefully. Decide, then act.
- Only reconsider a decision if a tool result contradicts it.
- There are no automated tests. After a change, tell the user what to check in the browser.
- Never start servers, watchers, or other background processes.
- Do not try to run, open, or verify the game yourself (webfetch cannot execute JavaScript).
- After a change, stop and tell the user what to check in the browser.
- After every change: commit, push, and give the user the raw GitHub link to the exact commit for index.html
  (https://raw.githubusercontent.com/danussbaum/claim/<full-sha>/index.html) so they can click and test right away.
